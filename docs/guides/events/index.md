# Events

An `Event` records one step of an agent invocation, combining model or user message content with metadata and an `EventActions` payload that describes state changes, artifact revisions, and control-flow signals. The `@google/adk` package provides factory functions to construct events with normalized defaults and helper functions to inspect tool calls, code execution results, reasoning traces, and turn completion.

## Introduction

Every turn processed by a `Runner` is represented as a sequence of `Event` objects yielded by agents and persisted by a session service. Instead of mutating session storage or control flow directly, an agent yields an `Event` whose `content` carries the message parts and whose `actions` field carries a declarative `EventActions` object.

Application code and custom `BaseAgent` implementations work with the events subsystem to construct events with `createEvent` and `createEventActions`, detect when a turn has reached a final user-facing answer with `isFinalResponse`, inspect tool activity with `getFunctionCalls` and `getFunctionResponses`, and filter or strip model reasoning parts with `stringifyContent`, `hasThoughts`, and `pruneThoughts`.

## Get started

The following example creates an `Event` with `createEvent` and `createEventActions`, populates missing function call identifiers with `populateClientFunctionCallId`, and inspects the event with the exported helper functions.

```ts
import {
  createEvent,
  createEventActions,
  getFunctionCalls,
  getFunctionResponses,
  hasThoughts,
  isFinalResponse,
  populateClientFunctionCallId,
  pruneThoughts,
  stringifyContent,
} from '@google/adk';

const toolCallEvent = createEvent({
  invocationId: 'inv-101',
  author: 'order_assistant',
  content: {
    role: 'model',
    parts: [
      {text: 'Checking order status first.', thought: true},
      {functionCall: {name: 'lookupOrder', args: {orderId: 'ORD-42'}}},
    ],
  },
});

populateClientFunctionCallId(toolCallEvent);

const finalEvent = createEvent({
  invocationId: 'inv-101',
  author: 'order_assistant',
  content: {
    role: 'model',
    parts: [
      {text: 'Drafting response for the customer.', thought: true},
      {text: 'Order ORD-42 has shipped.'},
    ],
  },
  actions: createEventActions({
    stateDelta: {lastOrderId: 'ORD-42'},
    artifactDelta: {'receipt_ORD-42.json': 0},
  }),
});

const callId = getFunctionCalls(toolCallEvent)[0]?.id;
const isToolCallFinal = isFinalResponse(toolCallEvent);
const isAnswerFinal = isFinalResponse(finalEvent);
const visibleText = stringifyContent(finalEvent);
const hasReasoning = hasThoughts(finalEvent);
const cleanedEvent = pruneThoughts(finalEvent);
const responseCount = getFunctionResponses(finalEvent).length;
```

## How it works

### Event construction and defaults

`Event` extends `LlmResponse` with invocation metadata, workflow routing fields, and an `actions` object. `createEvent(params)` accepts an optional `CreateEventParams` object, where `actions` can be a `Partial<EventActions>`, and fills in defaults for every required field. It brands the returned object with an internal symbol checked by the `isEvent` type guard, generates an 8-character alphanumeric `id` via `createNewEventId()` when `params.id` is omitted or empty, sets `invocationId` to `''` when omitted, initializes `actions` through `createEventActions(params.actions)`, defaults `longRunningToolIds` to `[]`, and records the creation time in milliseconds using `Date.now()`.

`createEventActions(state)` returns an `EventActions` object with empty objects `{}` for the four map fields, `stateDelta`, `artifactDelta`, `requestedAuthConfigs`, and `requestedToolConfirmations`, while leaving optional scalar and workflow fields `undefined` unless supplied in `state`.

### Final response detection

`isFinalResponse(event)` tells a caller or runner whether an event represents the terminal output of an agent turn. It returns `true` immediately when any of the following conditions holds:

- `event.actions.skipSummarization` is truthy.
- `event.longRunningToolIds` is present and contains at least one tool call ID.
- `event.actions.requestedAuthConfigs` is present and contains at least one key.

When none of those conditions holds, `isFinalResponse(event)` returns `true` only if `getFunctionCalls(event)` is empty, `getFunctionResponses(event)` is empty, `event.partial` is falsy, and `hasTrailingCodeExecutionResult(event)` is `false`.

### Function call, code execution, and thought helpers

`getFunctionCalls(event)` and `getFunctionResponses(event)` scan `event.content?.parts` and return all `FunctionCall` or `FunctionResponse` payloads in order. When a model emits a `FunctionCall` without an `id`, `populateClientFunctionCallId(event)` assigns one generated by `generateClientFunctionCallId()`, which prefixes a random UUID with `'adk-'`.

`hasTrailingCodeExecutionResult(event)` checks whether the final element of `event.content?.parts` carries a `codeExecutionResult`, allowing the runner to continue the model loop after code execution before treating the turn as complete.

For models that emit reasoning parts marked with `thought: true`, `hasThoughts(event)` reports whether any part has `thought === true`, `pruneThoughts(event)` returns a copy of the event with all `thought === true` parts removed from `content.parts`, and `stringifyContent(event)` concatenates the `text` of all non-thought parts into a single string.

## Configuration options

`createEvent` accepts `CreateEventParams`, and `createEventActions` accepts `Partial<EventActions>`.

### `Event` and `CreateEventParams` fields

| Option               | Type                                   | Default                | Description                                                                                                         |
| :------------------- | :------------------------------------- | :--------------------- | :------------------------------------------------------------------------------------------------------------------ |
| `id`                 | `string`                               | `createNewEventId()`   | Unique 8-character alphanumeric event identifier generated when omitted or empty.                                   |
| `invocationId`       | `string`                               | `''`                   | Identifier of the runner invocation that produced the event.                                                        |
| `author`             | `string`                               | `undefined`            | `'user'` or the name of the agent that appended the event to the session.                                           |
| `actions`            | `EventActions`                         | `createEventActions()` | Side effects and control-flow signals attached to the event; `CreateEventParams` accepts `Partial<EventActions>`.   |
| `longRunningToolIds` | `string[]`                             | `[]`                   | Function call IDs belonging to asynchronous long-running tools in a function call event.                            |
| `branch`             | `string`                               | `undefined`            | Dot-separated agent hierarchy path, such as `'agent_1.agent_2'`, used to isolate sub-agent conversation history.    |
| `timestamp`          | `number`                               | `Date.now()`           | Event creation timestamp in milliseconds since the Unix epoch.                                                      |
| `output`             | `unknown`                              | `undefined`            | Structured output value emitted by a workflow node.                                                                 |
| `route`              | `Route`                                | `undefined`            | Single `RouteKey` or array of `RouteKey` values (`string \| number \| boolean`) emitted by a routing workflow node. |
| `nodeInfo`           | `NodeInfo`                             | `undefined`            | Workflow node provenance containing `path`, `outputFor`, and `messageAsOutput`.                                     |
| `isolationScope`     | `string`                               | `undefined`            | Scope tag isolating multi-agent workflow conversations so peer scopes do not see each other's events.               |
| `content`            | `Content`                              | `undefined`            | Message payload inherited from `LlmResponse` containing `role` and `parts`.                                         |
| `partial`            | `boolean`                              | `undefined`            | Inherited from `LlmResponse`; `true` when the event is an incomplete streaming chunk.                               |
| `turnComplete`       | `boolean`                              | `undefined`            | Inherited from `LlmResponse`; `true` when the model turn finishes in streaming or live mode.                        |
| `interrupted`        | `boolean`                              | `undefined`            | Inherited from `LlmResponse`; `true` when model generation was interrupted.                                         |
| `errorCode`          | `string`                               | `undefined`            | Inherited from `LlmResponse`; machine-readable error code when a model call fails.                                  |
| `errorMessage`       | `string`                               | `undefined`            | Inherited from `LlmResponse`; human-readable error message when a model call fails.                                 |
| `groundingMetadata`  | `GroundingMetadata`                    | `undefined`            | Inherited from `LlmResponse`; search or citation grounding metadata from the model.                                 |
| `customMetadata`     | `Record<string, unknown>`              | `undefined`            | Inherited from `LlmResponse`; caller- or framework-supplied metadata preserved across case conversion.              |
| `usageMetadata`      | `GenerateContentResponseUsageMetadata` | `undefined`            | Inherited from `LlmResponse`; token usage counts reported by the model.                                             |

`id`, `invocationId`, `actions`, `longRunningToolIds`, and `timestamp` are always populated on the `Event` returned by `createEvent`. Note that `createEvent` uses `||` for `id`, `invocationId`, `longRunningToolIds`, and `timestamp`, so passing `''` for `id` or `0` for `timestamp` falls back to `createNewEventId()` or `Date.now()`.

### `EventActions` fields

| Option                       | Type                               | Default     | Description                                                                                               |
| :--------------------------- | :--------------------------------- | :---------- | :-------------------------------------------------------------------------------------------------------- |
| `skipSummarization`          | `boolean`                          | `undefined` | When `true` on a function response event, skips calling the model to summarize the tool output.           |
| `stateDelta`                 | `Record<string, unknown>`          | `{}`        | Key-value state updates applied to session, `user:`, `app:`, or `temp:` state when the event is appended. |
| `artifactDelta`              | `Record<string, number>`           | `{}`        | Map of artifact filename to zero-based revision number written during the step.                           |
| `transferToAgent`            | `string`                           | `undefined` | Name of the target agent to transfer control to immediately.                                              |
| `escalate`                   | `boolean`                          | `undefined` | Signals escalation to a parent or loop agent.                                                             |
| `requestedAuthConfigs`       | `Record<string, AuthConfig>`       | `{}`        | Map of function call ID to required `AuthConfig` when a tool requests user credentials.                   |
| `requestedToolConfirmations` | `Record<string, ToolConfirmation>` | `{}`        | Map of function call ID to a `ToolConfirmation` request awaiting user approval.                           |
| `agentState`                 | `Record<string, unknown>`          | `undefined` | Serialized workflow node or agent state snapshot used for resumable checkpointing.                        |
| `endOfAgent`                 | `boolean`                          | `undefined` | Marks that the emitting agent or workflow has reached the end of its execution for the invocation.        |

`stateDelta` and `artifactDelta` let an agent record side effects on the event stream so that `BaseSessionService.appendEvent` and downstream consumers can observe exactly which keys and artifact revisions changed on each turn.

## Advanced applications

### Emitting state and artifact deltas from a custom `BaseAgent`

When a custom `BaseAgent` saves an artifact through `ctx.artifactService`, capture the revision number returned by `saveArtifact` and record it in `actions.artifactDelta` alongside any `stateDelta` updates. Check that `ctx.artifactService` is defined before saving so that `artifactDelta` only advertises revisions that were actually written.

```ts
import {
  BaseAgent,
  createEvent,
  createEventActions,
  Event,
  InvocationContext,
} from '@google/adk';

export class ReceiptAgent extends BaseAgent {
  constructor() {
    super({
      name: 'receipt_agent',
      description: 'Saves an order receipt artifact and updates session state.',
    });
  }

  protected override async *runAsyncImpl(
    ctx: InvocationContext,
  ): AsyncGenerator<Event, void, void> {
    const artifactDelta: Record<string, number> = {};
    if (ctx.artifactService) {
      const revision = await ctx.artifactService.saveArtifact({
        filename: 'receipt.json',
        artifact: {
          text: JSON.stringify({
            appName: ctx.appName,
            orderId: 'ORD-42',
          }),
        },
      });
      artifactDelta['receipt.json'] = revision;
    }

    yield createEvent({
      invocationId: ctx.invocationId,
      author: this.name,
      branch: ctx.branch,
      content: {
        role: 'model',
        parts: [{text: 'Saved receipt for order ORD-42.'}],
      },
      actions: createEventActions({
        stateDelta: {lastOrderId: 'ORD-42'},
        artifactDelta,
      }),
    });
  }

  protected override async *runLiveImpl(
    ctx: InvocationContext,
  ): AsyncGenerator<Event, void, void> {
    yield* this.runAsyncImpl(ctx);
  }
}
```

### Stopping the model loop after a tool response

Set `skipSummarization: true` on a function response event's `actions` when the tool output should be treated as the final response for the turn without an additional model call.

```ts
import {createEvent, createEventActions, isFinalResponse} from '@google/adk';

const toolResponseEvent = createEvent({
  invocationId: 'inv-202',
  author: 'lookup_agent',
  content: {
    role: 'user',
    parts: [
      {
        functionResponse: {
          id: 'adk-call-1',
          name: 'lookupOrder',
          response: {status: 'SHIPPED'},
        },
      },
    ],
  },
  actions: createEventActions({skipSummarization: true}),
});

const done = isFinalResponse(toolResponseEvent); // true
```

## Limitations

- Events with `partial: true` represent in-flight streaming chunks; `BaseSessionService.appendEvent` does not persist them or apply their `stateDelta` to session storage.
- Keys prefixed with `temp:` in `actions.stateDelta` exist only for the active invocation and are stripped before session state is persisted.
- The `Symbol.for('google.adk.event')` brand attached by `createEvent` is not preserved across JSON serialization, so events reconstructed directly from plain JSON storage without `createEvent` do not carry the brand.
