# Authentication

ADK-JS provides a comprehensive authentication system that enables tools to request and manage credentials from users. The authentication framework supports multiple credential types and integrates with OAuth2, service accounts, and other authentication schemes.

## Authentication Credential Types

ADK-JS supports 5 authentication credential types defined in the `AuthCredentialTypes` enum:

```typescript
export enum AuthCredentialTypes {
  API_KEY = 'apiKey',
  HTTP = 'http',
  OAUTH2 = 'oauth2',
  OPEN_ID_CONNECT = 'openIdConnect',
  SERVICE_ACCOUNT = 'serviceAccount',
}
```

### 1. API_KEY

Simple API key authentication for services that use API keys.

```typescript
const authCredential: AuthCredential = {
  authType: AuthCredentialTypes.API_KEY,
  apiKey: 'your-api-key-here',
};
```

### 2. HTTP

HTTP authentication schemes (Basic, Bearer, etc.) following the IANA HTTP Auth Schemes registry.

```typescript
export interface HttpAuth {
  scheme: string;        // e.g., 'basic', 'bearer'
  credentials: HttpCredentials;
}

export interface HttpCredentials {
  username?: string;
  password?: string;
  token?: string;
}

// Example: Basic auth
const authCredential: AuthCredential = {
  authType: AuthCredentialTypes.HTTP,
  http: {
    scheme: 'basic',
    credentials: {
      username: 'user@example.com',
      password: 'secret',
    },
  },
};

// Example: Bearer token
const authCredential: AuthCredential = {
  authType: AuthCredentialTypes.HTTP,
  http: {
    scheme: 'bearer',
    credentials: {
      token: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...',
    },
  },
};
```

### 3. OAUTH2

OAuth2 authentication flows including authorization code, client credentials, implicit, and password grant types.

```typescript
export interface OAuth2Auth {
  clientId?: string;
  clientSecret?: string;
  authUri?: string;           // Generated by tool/ADK with state info
  state?: string;             // CSRF protection
  redirectUri?: string;       // Redirect URI for OAuth callback
  authResponseUri?: string;   // Response URI after authorization
  authCode?: string;          // Authorization code from OAuth flow
  accessToken?: string;       // Access token after exchange
  refreshToken?: string;      // Refresh token for token renewal
  expiresAt?: number;         // Token expiration timestamp
  expiresIn?: number;         // Token TTL in seconds
}

export enum OAuthGrantType {
  CLIENT_CREDENTIALS = 'client_credentials',
  AUTHORIZATION_CODE = 'authorization_code',
  IMPLICIT = 'implicit',
  PASSWORD = 'password',
}
```

### 4. OPEN_ID_CONNECT

OpenID Connect authentication which extends OAuth2.

Uses the same `OAuth2Auth` interface structure.

### 5. SERVICE_ACCOUNT

Google Cloud service account credentials.

See [Service Account Credentials](#service-account-credentials) section below.

## AuthCredential Interface

The base interface for all authentication credentials:

```typescript
export interface AuthCredential {
  authType: AuthCredentialTypes;
  resourceRef?: string;        // For future support
  apiKey?: string;
  http?: HttpAuth;
  serviceAccount?: ServiceAccount;
  oauth2?: OAuth2Auth;
}
```

## OAuth2 Authentication Flow

The OAuth2 flow in ADK-JS supports the complete authorization code flow:

### OAuth2Auth Fields

- **clientId**: OAuth2 client identifier
- **clientSecret**: OAuth2 client secret
- **authUri**: Authorization URI generated by tool/ADK with state info for client verification
- **state**: State parameter for CSRF protection
- **redirectUri**: Redirect URI for OAuth callback
- **authResponseUri**: The response URI after authorization
- **authCode**: Authorization code from OAuth flow
- **accessToken**: Access token after exchange
- **refreshToken**: Refresh token for token renewal
- **expiresAt**: Token expiration timestamp
- **expiresIn**: Token TTL in seconds

### OAuth2 Flow Sequence

1. **Tool/ADK generates authUri** with state info for verification
2. **Tool/ADK sets redirectUri** if they want to control the callback
3. **Raw credential is exchanged** through AuthHandler and credential exchanger system
4. **Client uses authUri** to guide user through OAuth2 flow
5. **Auth response is filled** in the exchangedAuthCredential field
6. **Tool retrieves credential** via getAuthResponse()

## Requesting and Retrieving Credentials

Tools use `ToolContext` methods to request credentials from users and retrieve collected credentials.

### ToolContext.requestCredential()

Triggers credential collection by creating an authentication request.

```typescript
requestCredential(authConfig: AuthConfig): void
```

**How it works:**
1. Requires `functionCallId` to be set (throws error if not)
2. Creates an `AuthHandler` with the provided `authConfig`
3. Calls `authHandler.generateAuthRequest()` to process the auth scheme and generate authorization URI if needed
4. Stores the auth request in `eventActions.requestedAuthConfigs[functionCallId]`
5. Signals to the system that credentials are needed, which will be surfaced to the client

**Example:**

```typescript
class MyTool extends FunctionTool {
  override async execute(args: unknown, context: ToolContext) {
    const authConfig: AuthConfig = {
      credentialKey: 'github_token',
      authScheme: {
        type: 'oauth2',
        flows: {
          authorizationCode: {
            authorizationUrl: 'https://github.com/login/oauth/authorize',
            tokenUrl: 'https://github.com/login/oauth/access_token',
          },
        },
      },
      rawAuthCredential: {
        authType: AuthCredentialTypes.OAUTH2,
        oauth2: {
          clientId: 'your-client-id',
          clientSecret: 'your-client-secret',
        },
      },
    };

    context.requestCredential(authConfig);

    // Wait for credential to be provided
    // ...
  }
}
```

### ToolContext.getAuthResponse()

Retrieves the collected credential from session state.

```typescript
getAuthResponse(authConfig: AuthConfig): AuthCredential | undefined
```

**How it works:**
1. Creates an `AuthHandler` with the `authConfig`
2. Calls `authHandler.getAuthResponse(state)` to look up the credential
3. The credential is stored with key `'temp:' + authConfig.credentialKey`
4. Returns the `AuthCredential` if found, `undefined` otherwise

**Example:**

```typescript
class MyTool extends FunctionTool {
  override async execute(args: unknown, context: ToolContext) {
    const authConfig: AuthConfig = {
      credentialKey: 'github_token',
      authScheme: {type: 'oauth2'},
    };

    // Try to get existing credential
    const credential = context.getAuthResponse(authConfig);

    if (!credential) {
      // Request credential if not found
      context.requestCredential(authConfig);
      return {partial: 'Please provide GitHub authentication.'};
    }

    // Use the credential
    const accessToken = credential.oauth2?.accessToken;
    // Make authenticated API calls...
  }
}
```

## AuthConfig

The `AuthConfig` interface coordinates the authentication flow between tools, ADK, and clients.

```typescript
export interface AuthConfig {
  authScheme: AuthScheme;
  rawAuthCredential?: AuthCredential;
  exchangedAuthCredential?: AuthCredential;
  credentialKey: string;
}
```

### Field Purposes

#### authScheme

The authentication scheme from OpenAPI 3.0 spec (e.g., oauth2, apiKey, http, openIdConnect) that defines how to collect credentials.

#### rawAuthCredential

The raw auth credential used to collect credentials. Used in auth schemes that need credential exchange (OAuth2, OIDC).

- For OAuth2/OIDC: Contains initial data like `clientId`/`clientSecret`
- For other schemes (API key, service account): `undefined`

#### exchangedAuthCredential

The credential after processing/exchange. ADK and client work together to fill it:

- **For non-exchange schemes** (API key, service account): Filled directly by client
- **For exchange schemes** (OAuth2, OIDC):
  - First filled by ADK with generated `authUri` and `state`
  - If raw credentials already have `authUri`, it's copied here
  - Client uses this field to guide user through OAuth2 flow
  - Client fills auth response here

#### credentialKey

A user-specified key used to load and save this credential in the credential service. Used to identify and retrieve stored credentials.

### AuthConfig Usage Flow

1. Tool calls `requestCredential()` with an `AuthConfig`
2. `AuthHandler.generateAuthRequest()` processes `rawAuthCredential` and populates `exchangedAuthCredential` with `authUri`
3. Client receives the `AuthConfig` and guides user through auth flow
4. User provides credentials which are stored in session state at `'temp:' + credentialKey`
5. Tool calls `getAuthResponse()` to retrieve the credential from state

## BaseCredentialService and InMemoryCredentialService

The credential service provides persistent storage for user credentials.

### BaseCredentialService Interface

```typescript
export interface BaseCredentialService {
  loadCredential(
    authConfig: AuthConfig,
    toolContext: ToolContext,
  ): Promise<AuthCredential | undefined>;

  saveCredential(
    authConfig: AuthConfig,
    toolContext: ToolContext,
  ): Promise<void>;
}
```

#### loadCredential()

Loads credential from backend store using `authConfig.credentialKey` to build the lookup key.

**Returns:** `Promise<AuthCredential | undefined>`

#### saveCredential()

Saves the `exchangedAuthCredential` from `authConfig` to the backend store using `authConfig.credentialKey` as the key.

**Returns:** `Promise<void>`

### InMemoryCredentialService Implementation

Provides in-memory credential storage (experimental, subject to change).

```typescript
export class InMemoryCredentialService implements BaseCredentialService {
  private readonly credentials: Record<
    string,  // appName
    Record<string,  // userId
      Record<string, AuthCredential>  // credentialKey -> credential
    >
  > = {};

  loadCredential(
    authConfig: AuthConfig,
    toolContext: ToolContext,
  ): Promise<AuthCredential | undefined> {
    const credentialBucket = this.getBucketForCurrentContext(toolContext);
    return Promise.resolve(credentialBucket[authConfig.credentialKey]);
  }

  async saveCredential(
    authConfig: AuthConfig,
    toolContext: ToolContext,
  ): Promise<void> {
    const credentialBucket = this.getBucketForCurrentContext(toolContext);
    if (authConfig.exchangedAuthCredential) {
      credentialBucket[authConfig.credentialKey] =
        authConfig.exchangedAuthCredential;
    }
  }

  private getBucketForCurrentContext(
    toolContext: ToolContext,
  ): Record<string, AuthCredential> {
    const {appName, userId} = toolContext.invocationContext.session;
    // Lazily initialize nested structure
    if (!this.credentials[appName]) {
      this.credentials[appName] = {};
    }
    if (!this.credentials[appName][userId]) {
      this.credentials[appName][userId] = {};
    }
    return this.credentials[appName][userId];
  }
}
```

**Storage Structure:**
- Three-level nested Record: `credentials[appName][userId][credentialKey] = AuthCredential`
- User-scoped credential storage where each app/user combination has isolated credential storage

**Usage:**

```typescript
const credentialService = new InMemoryCredentialService();

const runner = new Runner({
  agent: myAgent,
  sessionService: sessionService,
  credentialService: credentialService,
});
```

## Credential Exchanger Registry

The credential exchanger system enables transforming credentials from one format to another.

### BaseCredentialExchanger Interface

```typescript
export interface BaseCredentialExchanger {
  exchange({authCredential, authScheme}: {
    authCredential: AuthCredential;
    authScheme?: AuthScheme;
  }): Promise<AuthCredential>;
}
```

**Parameters:**
- `authCredential` - The credential to exchange
- `authScheme` - Optional auth scheme (some exchangers don't need it)

**Returns:** The exchanged credential

**Throws:** `CredentialExchangeError` if exchange fails

### CredentialExchangerRegistry

Manages credential exchanger instances per credential type.

```typescript
export class CredentialExchangerRegistry {
  private exchangers: Partial<
    Record<AuthCredentialTypes, BaseCredentialExchanger>
  > = {};

  register(
    credentialType: AuthCredentialTypes,
    exchangerInstance: BaseCredentialExchanger,
  ): void {
    this.exchangers[credentialType] = exchangerInstance;
  }

  getExchanger(
    credentialType: AuthCredentialTypes,
  ): BaseCredentialExchanger | undefined {
    return this.exchangers[credentialType];
  }
}
```

**Example Use Cases:**
- OAuth2 credentials: Exchange authorization code for access tokens
- Service account credentials: Exchange key files for access tokens

**Example Custom Exchanger:**

```typescript
class OAuth2Exchanger implements BaseCredentialExchanger {
  async exchange({authCredential, authScheme}) {
    const oauth2 = authCredential.oauth2;
    if (!oauth2?.authCode) {
      throw new Error('Authorization code required');
    }

    // Exchange authCode for access token
    const response = await fetch(authScheme.tokenUrl, {
      method: 'POST',
      body: JSON.stringify({
        grant_type: 'authorization_code',
        code: oauth2.authCode,
        client_id: oauth2.clientId,
        client_secret: oauth2.clientSecret,
        redirect_uri: oauth2.redirectUri,
      }),
    });

    const tokens = await response.json();

    return {
      authType: AuthCredentialTypes.OAUTH2,
      oauth2: {
        ...oauth2,
        accessToken: tokens.access_token,
        refreshToken: tokens.refresh_token,
        expiresIn: tokens.expires_in,
      },
    };
  }
}

// Register the exchanger
const registry = new CredentialExchangerRegistry();
registry.register(AuthCredentialTypes.OAUTH2, new OAuth2Exchanger());
```

## AuthHandler

The `AuthHandler` class orchestrates the authentication flow between tools, ADK, and clients.

### Constructor

```typescript
constructor(private readonly authConfig: AuthConfig)
```

Takes an `authConfig` parameter and stores it as a private readonly field.

### getAuthResponse()

Retrieves the collected credential from session state.

```typescript
getAuthResponse(state: State): AuthCredential | undefined
```

**Implementation:**
- Constructs the credential key as `'temp:' + this.authConfig.credentialKey`
- Returns `state.get<AuthCredential>(credentialKey)`
- Returns `undefined` if credential not found

### generateAuthRequest()

Processes the auth request and generates necessary URIs.

```typescript
generateAuthRequest(): AuthConfig
```

**Flow:**

1. Gets `authSchemeType` from `authConfig.authScheme.type`

2. **For non-OAuth schemes** (not 'oauth2' or 'openIdConnect'):
   - Returns `authConfig` as-is

3. **For OAuth/OIDC schemes with existing authUri**:
   - If `exchangedAuthCredential` already has `oauth2.authUri`, returns `authConfig` as-is

4. **For OAuth/OIDC schemes needing auth URI generation**:
   - Validates `rawAuthCredential` exists (throws error if not)
   - Validates `rawAuthCredential.oauth2` exists (throws error if not)
   - If `oauth2.authUri` already exists in raw credential, copies it to `exchangedAuthCredential`
   - Otherwise, validates `clientId` and `clientSecret` are present (throws error if not)
   - Calls `generateAuthUri()` to generate the authorization URI
   - Returns `AuthConfig` with `credentialKey`, `authScheme`, `rawAuthCredential`, and `exchangedAuthCredential`

### generateAuthUri()

Currently returns `this.authConfig.rawAuthCredential`. Full implementation is pending (TODO: b/425992518).

Intended to generate an auth URI with state for user sign-in.

## Service Account Credentials

The `ServiceAccountCredential` type represents Google Cloud service account configuration.

### ServiceAccountCredential Interface

```typescript
export interface ServiceAccountCredential {
  type: 'service_account';
  projectId: string;
  privateKeyId: string;
  privateKey: string;
  clientEmail: string;
  clientId: string;
  authUri: string;
  tokenUri: string;
  authProviderX509CertUrl: string;
  clientX509CertUrl: string;
  universeDomain: string;
}
```

**Example:**

```typescript
const serviceAccountCred: ServiceAccountCredential = {
  type: "service_account",
  projectId: "your_project_id",
  privateKeyId: "your_private_key_id",
  privateKey: "-----BEGIN PRIVATE KEY-----...",
  clientEmail: "...@....iam.gserviceaccount.com",
  clientId: "your_client_id",
  authUri: "https://accounts.google.com/o/oauth2/auth",
  tokenUri: "https://oauth2.googleapis.com/token",
  authProviderX509CertUrl: "https://www.googleapis.com/oauth2/v1/certs",
  clientX509CertUrl: "https://www.googleapis.com/robot/v1/metadata/x509/...",
  universeDomain: "googleapis.com",
};
```

### ServiceAccount Interface

Wraps the credential with additional options:

```typescript
export interface ServiceAccount {
  serviceAccountCredential?: ServiceAccountCredential;
  scopes?: string[];
  useDefaultCredential?: boolean;
}
```

**Fields:**
- `serviceAccountCredential` - The full credential object
- `scopes` - OAuth scopes to request
- `useDefaultCredential` - Flag to use Application Default Credentials instead of explicit key file

### Usage Patterns

#### 1. Explicit Key File

Provide full `ServiceAccountCredential` with all fields populated:

```typescript
const authCredential: AuthCredential = {
  authType: AuthCredentialTypes.SERVICE_ACCOUNT,
  serviceAccount: {
    serviceAccountCredential: {
      type: 'service_account',
      projectId: 'my-project',
      privateKeyId: 'key-id',
      privateKey: '-----BEGIN PRIVATE KEY-----\n...',
      clientEmail: 'service@my-project.iam.gserviceaccount.com',
      clientId: '123456789',
      authUri: 'https://accounts.google.com/o/oauth2/auth',
      tokenUri: 'https://oauth2.googleapis.com/token',
      authProviderX509CertUrl: 'https://www.googleapis.com/oauth2/v1/certs',
      clientX509CertUrl: 'https://www.googleapis.com/robot/v1/metadata/x509/...',
      universeDomain: 'googleapis.com',
    },
    scopes: ['https://www.googleapis.com/auth/cloud-platform'],
  },
};
```

#### 2. Default Credentials

Set `useDefaultCredential: true` to use Google's Application Default Credentials (ADC):

```typescript
const authCredential: AuthCredential = {
  authType: AuthCredentialTypes.SERVICE_ACCOUNT,
  serviceAccount: {
    useDefaultCredential: true,
    scopes: ['https://www.googleapis.com/auth/cloud-platform'],
  },
};
```

ADC automatically discovers credentials from:
- `GOOGLE_APPLICATION_CREDENTIALS` environment variable
- gcloud CLI configuration
- Compute Engine/Cloud Run/GKE metadata server

## Complete Authentication Example

```typescript
import {
  FunctionTool,
  ToolContext,
  AuthConfig,
  AuthCredentialTypes,
  InMemoryCredentialService,
  Runner,
} from '@google/adk';

class GitHubTool extends FunctionTool {
  constructor() {
    super({
      name: 'github_api',
      description: 'Access GitHub API',
      execute: async (args: unknown, context: ToolContext) => {
        return this.executeImpl(args, context);
      },
    });
  }

  private async executeImpl(args: unknown, context: ToolContext) {
    const authConfig: AuthConfig = {
      credentialKey: 'github_oauth',
      authScheme: {
        type: 'oauth2',
        flows: {
          authorizationCode: {
            authorizationUrl: 'https://github.com/login/oauth/authorize',
            tokenUrl: 'https://github.com/login/oauth/access_token',
            scopes: {
              'repo': 'Access repositories',
              'user': 'Access user data',
            },
          },
        },
      },
      rawAuthCredential: {
        authType: AuthCredentialTypes.OAUTH2,
        oauth2: {
          clientId: process.env.GITHUB_CLIENT_ID,
          clientSecret: process.env.GITHUB_CLIENT_SECRET,
        },
      },
    };

    // Try to get existing credential
    const credential = context.getAuthResponse(authConfig);

    if (!credential?.oauth2?.accessToken) {
      // Request credential if not found or incomplete
      context.requestCredential(authConfig);
      return {
        partial: 'Please authenticate with GitHub to continue.',
      };
    }

    // Use the access token
    const response = await fetch('https://api.github.com/user/repos', {
      headers: {
        'Authorization': `Bearer ${credential.oauth2.accessToken}`,
        'Accept': 'application/vnd.github.v3+json',
      },
    });

    const repos = await response.json();
    return {repositories: repos};
  }
}

// Setup runner with credential service
const credentialService = new InMemoryCredentialService();

const runner = new Runner({
  agent: myAgent,
  sessionService: sessionService,
  credentialService: credentialService,
  plugins: [],
});
```
